# UI 默认状态与首帧修复

本次从 `1849efb3` 检查“动作按钮点击后持续高亮”和“页面显示后才补样式、行高或间距”的问题。默认外观和几何由共享组件负责，页面继续声明动作语义、布局类型和真实业务状态。默认准备不触发设备查询、驱动操作或隐藏页业务构造。

## 按钮状态

进程列表顶部设置齿轮是非勾选 `QPushButton`，经 `ApplyFlatButtonTheme(Neutral, Solid)` 接入。原共享 QSS 将 `:focus` 与 `:hover` 合并，鼠标离开后按钮保留焦点，仍显示悬停强调底；原生焦点绘制还可能叠加浅蓝背景。

共享过滤器现在按输入来源显示键盘焦点：鼠标操作恢复常态，Tab、Shift+Tab、快捷键和键盘操作保留可辨提示。菜单或设置窗口关闭后的焦点恢复沿用真实输入来源，不清除实际焦点，也不改变焦点策略。勾选、禁用和按下状态保持原业务含义。动态图标与两类 Hex 自绘按钮使用同一实际状态；折叠分区也使用相同键盘焦点判据。

## 逐项检查范围

主程序扫描了 1235 个 `.cpp/.h` 和 710 个排队调用，按完整调用体筛选 32 个直接样式/几何候选，并检查共享间接入口、显示事件和各 Dock 的相关路径。进程列表、线程、Cross-View、创建进程及设置/选择列窗口单独复核。

另检查 15 个自有辅助目录共 535 个源码、表单和样式文件，补查 Win32、FLTK 和独立 Qt 应用。完整候选、101 行显示/延迟索引及逐项理由见 [逐项审计](UI默认状态逐项审计-20261025.md)。Taskbar、HUD 使用独立组件，分别修复；保留 ARKLight 线程详情原生布局时序及 Taskbar 原生背景窗时序，并明确尚未完成相应 Windows 实机视觉验证。

仅有零延时队列不代表会产生首帧问题。`FloatingScrollbars` 原实现的真实 Qt 首显矩阵通过；强行在 UpdateRequest 提前安装反而出现 14px 视口跳动，因此保留原实现。新表格动作条的初配边界也与真实 Floating、ThemeBinding 联测，避免只修动作条却引入滚动区跳变。

异步结果回投中的状态颜色、导入/预览窗口显示前构造、组合框 Popup 显示栈保护，以及已有正确同步准备的页签/详情框架均已分类，不作为普通默认间距问题改写。

## 可重复验证

将 `KSWORD_QT_DIR` 指向 Qt SDK 根目录，然后运行：

```bash
python tools/run_shared_ui_regressions.py --qt-dir "$KSWORD_QT_DIR"
```

Windows 从 HostX64/x64 MSVC 环境运行，并提供 64 位 MSBuild：

```powershell
python tools/run_shared_ui_regressions.py --qt-dir $env:KSWORD_QT_DIR --msbuild $msbuild
```

回归分别覆盖真实鼠标/键盘、首个实际 Paint 与队列稳定后几何、普通/弹窗边界、深浅主题、大字号、宽窄重显、实际控件销毁和重复无变化更新。旧源码反证用于确认测试能够抓住原问题。

第一轮统一入口的十组回归全部通过：按钮 584、工具行 70、参数布局 245、二级表单 50、主题 108、消息框 33、详情 1218、监视 68、动态表格 120、辅助窗口 116 项检查。Windows CI 使用 Qt 6.9.3、MSVC HostX64/x64 运行同一入口，再构建实际产品。

详情布局还覆盖顶层与嵌入式父窗自动显示、四种布局方案、显式隐藏、同步重绑及销毁，共 200 个场景、1218 项检查；普通构建连续运行五次、AddressSanitizer 连续运行三次通过。旧版同一组检查有 64 项自然首帧布局失败。显示栈中直接重挂子树的方案会使 Qt 自身的子控件遍历失效，因此最终使用 `ShowToParent` 和可见布局完成边界，而非提前修改 Show 遍历中的结构。

测试使用实际 QtWidgets 和相应生产实现；特定夹具对业务采样、编辑器内容、动作条业务或平台图标使用薄适配，边界写在各 runner 中。这些组件回归不等同于逐页运行 Windows 主程序、真实 ADS/GPU/浮窗/多屏 DPI 或测得整体加载速度。完整产品 GUI 的视觉与实际性能需分别验收。

## 自动焦点转移补漏

后续截图反馈后，复现了第一轮未覆盖的错误：鼠标焦点按钮被禁用或隐藏时，Qt 自动把焦点交给邻居，但事件仍使用 `TabFocusReason`。旧共享过滤器仅按此原因判断键盘输入，于是邻居未被点击、未悬停、未选中也会变蓝。在真实应用主题与调色板下，底色由 `#243040` 变成 `#43a0ff`。第一轮夹具先清除焦点再禁用，未观察自动承接者；其通过不能覆盖此路径。

本轮复用既有应用事件过滤器记录真实输入，区分鼠标自动转焦和真实 Tab/Backtab。仅依赖 Qt 窗口键盘标志仍不足，因为真 Tab 后点击已持焦点的同一按钮，原生标志可能保持旧值。单独 Ctrl、Shift、Alt、Meta 等修饰键也不应把普通动作误点亮。鼠标在空白或其他窗口操作后，以最近的实际输入决定恢复提示；真实键盘操作、程序化关闭以及业务勾选状态分别保留。Taskbar 独立绘制的 PageEntry 修复相同判断，并使用一个应用拥有、仅记录输入的轻量跟踪器；没有新增轮询、全树扫描或焦点策略修改。

新增 `tools/test_button_theme_integration_ui.py` 使用真实 StandardWidgetTheme、FlatButtonTheme、MainSurfaceStyle、ThemeBinding、GlobalUiBaseStyle 与主窗口调色板，保留实际主题登记及队列。无关非按钮角色为明确薄适配；Windows 使用真实系统动画查询，Linux 只适配该未参与按钮行为的 Win32 查询。鼠标关闭、Escape 关闭和程序关闭窗口分别测试，且真正移开光标后再判断常态。

本地主按钮矩阵扩展为 610 项通过，旧 `d628861b` 同套 24 项失败；新增完整主题集成 103 项通过，旧版同样成功编译运行后有 14 项行为失败。新增集成已加入统一入口，Windows 继续使用相同回归作为正式构建的前置检查。

Taskbar 与 HUD 的组合回归扩展为 142 项通过，旧 `d628861b` 同套有 11 项失败；本轮 HUD 实现与原有用例未改。最终统一十一组在本地真实 Qt 环境合计 2767 项通过。上述本地结果不作为尚未执行的 Windows 完整产品 GUI 结论。

截图中的 CPU、内存、磁盘、网络、GPU 是默认开启、直接控制曲线显隐的独立开关，本轮未将其业务 checked 状态改成关闭。普通悬停与 checked 同色的现有配方也未作为“鼠标已移开仍残留”的证据；本轮修复的是已实际复现的输入来源误判。
