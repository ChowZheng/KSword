# 监控部分筛选器与分类现状

范围：`KswordARKLight/Features/Monitor/`（ETW 监控页、内核回调监控页）。
目的：记录两页各自能筛什么、分类按什么分、以及**为什么**这么分，避免下次
改动时把已经想清楚的口径改回去。

---

## 1. 两页对照

| | ETW 监控（`EtwMonitorView`） | 回调监控（`CallbackMonitorView`） |
|---|---|---|
| 文本筛选 | `FilterBar`，支持正则开关 | `EDIT` + 180ms 防抖计时器 |
| 结构化筛选 | **分类下拉 + 级别下拉**（本轮新增） | **六个类别复选框**（已有） |
| 分类维度 | 进程 / 线程 / 映像 / 文件 / 注册表 / 网络 / 安全 / 其他 | 进程 / 线程 / 映像 / 注册表 / 对象 / 文件 |
| 分类列 | 第 7 列「分类」（本轮新增） | 第 2 列「类别」（已有） |
| 导出 | 可见行 TSV（八列，含分类） | 可见行 TSV |

结论：**分类不是缺项，缺的是 ETW 页那一半**。回调页一开始就按回调类型给了
复选框，ETW 页只有一个文本框，用户想「只看文件类事件」只能猜一个能命中摘要
的词，而摘要里出现「文件」两个字的事件，和真正操作文件的事件不是一回事。

---

## 2. ETW 分类口径（`EtwEventClassifier`）

**判定顺序：provider 名 → 摘要关键字 → 其他。**

provider 名优先，是因为 ETW provider 的名字沿用微软自己的拼写
（`Microsoft-Windows-Kernel-File` 等），不随系统语言变化；摘要文本会。

规则表（provider）刻意只收录信号明确的项：

| 命中片段 | 归类 |
|---|---|
| `kernel-file` | 文件 |
| `kernel-registry` | 注册表 |
| `kernel-process` / `kernel-object` | 进程 |
| `kernel-thread` | 线程 |
| `kernel-image` | 映像 |
| `kernel-network` / `tcpip` / `ndis` / `dns-client` | 网络 |
| `security-auditing` / `kernel-audit-api` / `amsi` | 安全 |

摘要兜底的规则更窄：`\registry\`、`hklm\` 之类才归注册表，单出现「文件」两个
字不算强信号（这是文件类规则里唯一放宽的一条，因为 ETW 摘要普遍很短）。

**认不出来就落「其他」，这是故意的。** 调查工具里分类错了比不分类更糟：用户
会照着这个分类筛，然后就再也不看别处了。宁可让「其他」鼓起来，让用户知道
分类器不认识这类事件。

**不改 `shared/` 里的 `EtwEvent` 结构。** 分类完全在 Light 的视图层算出来，
一是避免牵连正处在火焰图施工期的 Qt 侧，二是分类是展示口径，不该进数据模型。

---

## 3. 级别筛选

按 ETW 原生级别 1..5 对齐：1 严重、2 错误、3 警告、4 信息、5 详细。

下拉索引 0 是「全部级别」，索引 n 就是 `level == n`，所以比较是一次等值判断，
不需要维护一张映射表。

---

## 4. 异步筛选的正确性约束（改这块必须先看）

ETW 页的筛选是**按序号增量**跑的：`filteredThroughSequence_` 记录已经滤到哪，
新事件只滤尾巴。这套机制有三个必须同时满足的条件：

1. **所有筛选输入都要进 `changed` 判定**。漏一个，改那个输入就不会 bump
   `localFilterGeneration_`，也就不会把 `filteredThroughSequence_` 退回起点，
   结果是一份前半段按旧条件、后半段按新条件的列表。
2. **所有筛选输入都要进 `applyLocalFilter` 的陈旧校验**。漏一个，一次在途的
   旧结果会被当成新结果接受。
3. **空文本查询不能直接短路成「显示全部」**。分类+级别本身就是合法筛选条件，
   查询为空时必须继续走任务。

本轮新增 `categoryFilter` / `levelFilter` 时，这三处都一并改了。以后再加
筛选维度，照这三条抄。

---

## 5. 导出与列序

ETW 页现在**不复用** `shared/.../BuildVisibleEtwEventsTsv`：那个函数写七列
（PID/时间/Provider/TID/EventId/Level/摘要），不认识分类列。用了就会给用户
一份表头和自己刚才看的表对不上的文件。

页面自己按屏幕列序拼八列，`Ui::SanitizeTsvCell` 处理每个文本单元格。

---

## 6. 还没做的

- **ETW 分类分布统计**：状态栏目前只报「筛选结果 N 项；分类 X；级别 Y」。
  更想要的是「当前缓冲里各类各多少条」，但那需要在每次 flush 时遍历一遍，
  和增量筛选的账算在一起容易出错，留作下一步。
- **回调页与 ETW 页的分类口径不统一**（回调有「对象」没有「网络/安全」，
  ETW 反之）。两页数据源不同，强行统一会削掉各自有意义的类目，暂不合并。
