# 本机快捷键清除与运行时规则匹配

## 功能与导航

| 入口 | 页面类型和共享入口 | 行为 |
| --- | --- | --- |
| 窗口 → 热键/钩子 → 程序快捷键 | 主列表；ImmutableValueTable、Full操作条、AsyncOperation | 多选清除窗口激活热键和快捷方式文件的热键设置 |
| 窗口 → 热键/钩子 → 注册热键 | 现场清单；同一结果表和共享异步事务 | 当前映像通过运行时规则证明后，按完整身份重新枚举并清除普通独立注册项 |
| 杂项 → 快捷键管理 | 生命周期/状态及导航代理；共享页根、动作行和主题 | 跳转现有管理实例；不创建第二份列表或扫描器 |
| 进程属性 → 进程热键 | 属性详情中的主列表；原详情框架 | 单项删除复用同一清除后端，编辑路径保留 |

菜单文字、PE Accelerator程序资源、回调、占位项和含子项的注册对象不伪装成可清除项。
选中这些来源时显示原因；混合选择按来源统计并跳过不支持的项。
快捷方式清除只验证文件配置，通知Shell更新不代表已验证Explorer的运行时注册已经消失。

规范目标随原始结果保留：列表排序/筛选后由模型角色中的稳定token和刷新代次取回目标，不能从显示文本或可视行号拼清除请求。
清除前确认一次选择；后台逐项执行，分别显示成功、跳过、失败或未确认的回执，结束后真实刷新一次。
窗口/文件/进程身份和原值在执行前再次检查；超时与读回失败不表示确定成功或确定未修改。
进程详情的模态确认返回后还复核存活、PID/创建时间、结果快照和选区身份。

杂项入口追加在原目录末尾，保留既有索引；目录预加载不触发导航或枚举。
MainWindow的惰性和常规构造路径共用一次信号接线，按真实页对象激活，失败保留状态和重试动作。
同类主列表对照了窗口总表、进程热键页；系统时间/虚拟位置参数页仅作页面分类对照，没有把结果列表误套参数表单。

本机双文件的 PE 固定版本均为 `10.0.26100.9022`。以下身份来自实际文件；它是本次取证的一组样本，当前运行时规则不按该身份查目录授权。

本机 `NtUserUnregisterHotKey` 在调用 Base 的 `EnterCrit` 前把 ECX、EDX 置零；Base 实际读取这两个参数。Full 用 `win32k.sys!W32GetUserSessionState` 的返回值访问同一会话热键表，不能换用 `UserGetSiloGlobals`。本机证明出的扫描函数与单节点 helper 是两个入口：`ScanRva=0x1C8108`，`RemoveRva=0x285BA0`；表偏移 `0x3290`、缓存偏移 `0x36A8`、桶数 128、节点 72 字节。上述 RVA 只标识这一份文件中的实际指令，不是未来版本的匹配表。

本机既有的 [自动匹配报告](hotkey_matching/local-26100.9022-match.json)、[IDA 实际指令](hotkey_matching/win32kfull-26100.9022-ida-functions.json)和[会话入口与 ABI 指令](hotkey_matching/local-session-abi-20261025.json)仍可用于核对该样本。六组双文件的身份、布局变化、SGD/W32 getter、owner/window 来源与内联/独立扫描差异见[跨版本规则匹配记录](快捷键跨版本规则匹配-20261025.md)。

## 当前运行时规则与变更门禁

驱动通过同一套有界生产 C 规则读取**当前实际映像**：从真实导出与导入槽、函数边界和指令数据流证明注册节点字段、桶循环、同源 owner/window/ID 筛选、插入与卸载缓存位、一参链槽 helper 的摘链及释放。缺失、歧义、代码变化或预算不足均不发布可调用结果。当前运行时不以 Windows build、PE/RSDS 身份名单或逐版本生成的 profile 选择布局；代码与元数据指纹仅用于本次证明后的失效复核。

读取与变更继续保留原调用者 USER 会话。驱动绑定与 Full 实际导入一致的 W32/SGD getter，并把会话 ID 与 namespace 指针分别核对；规范 PID/TID 归属、读取失败、环与预算耗尽的状态不应被空成功覆盖。变更只受理完整快照、唯一身份、普通独立节点、空子链和匹配的调用者上下文，进入临界区前后复核证明与当前值。单槽 helper 返回零时也可能有副作用，因此以重新枚举和读回决定回执，不能由布尔值推断未修改。

键盘 R0/R3 协议当前为 **v4**（`shared/driver/KswordArkKeyboardIoctl.h`）：枚举行携带实际 SessionId，变更请求携带 expectedSessionId；SessionId 为零仍可表示真实 System 会话。namespace 指针与 SessionId 各自验证，旧协议的变更请求不得进入新写路径。主程序、共享协议和驱动需要配套使用。

## 已取代的逐版本目录方案

早期 `tools/pdb_offset_generator/match_win32k_hotkeys.py` 曾生成逐配对的 `keyboard_profiles.generated.h`。当前已删除生成头，工具改为调用与驱动相同的 C 引擎；历史报告仅保留为取证材料。旧方案“为每个版本下载样本、生成表项、按双 PE/RSDS 与函数头选 profile”不再参与运行时授权。新文件配对通过同一规则自动推导，无需手工添加版本或 RVA 表项；未知构型未通过规则时明确拒绝。

## 验证状态

- 生产 C 规则对六组真实 AMD64 FULL/BASE 配对 **6/6 匹配**；新旧测试入口均调用同一引擎，离线规则用例 **22/22 通过**。输入未执行或加载。源码、样本、探针哈希和逐项结果见[正式验证报告](hotkey_matching/runtime-rule-validation-20261025.json)。清除身份回归另有 **40 项、0 失败**。
- 主程序标准 Release/x64 构建成功，语言包审计通过。标准 MSVC/WDK 驱动构建成功，`Driver is 'Universal'.`，签名适用性与目录生成均无错误、无警告。产物仍在 `Ksword5.1/x64/Release/`；驱动本轮跳过可选签名，实际文件为 `NotSigned`。详见[构建记录](快捷键跨版本规则匹配-20261025.md#构建记录)。
- 全桶唯一性现在同时保护清除与修改；修改副作用未确认时保留未知回执并刷新。实际 GUI、DPI/主题/窄窗、驱动加载、USER 会话中的窗口/快捷方式/注册热键清除效果由用户实机验收；离线匹配及编译通过不代表实际清除已验证。
