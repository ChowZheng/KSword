# 内核池分配分析

入口：内存 → 系统内存审计 → PFN 深度归因 → GPU / 分配历史 → Pool 分配分析。

点击“采集 Pool 分配历史”，选择 ETL 保存位置并设置采集秒数。保存成功后自动打开分析结果。也可以在分析页打开已有 ETL；加载已有文件不启动录制或驱动。

## 阅读结果

表格支持按 Pool Tag、完整调用栈或历史栈模块聚合，以及文本筛选。默认按“未观察到释放”的字节数排序。选择一行后可以切换该行包含的原始分配栈，查看每帧地址、历史模块和模块内偏移；按需解析本地匹配映像的符号，并打开本机模块文件详情。

模块分组取栈中首个不属于 ntoskrnl/HAL 的已解析模块，没有时回退到内核映像。这个字段表示调用路径来源，不能单凭栈中出现某个模块确定泄漏责任。历史映像 ID 隔离卸载及同基址重新加载的模块；未知模块保留原始地址。

当前读取器只将 PID 为 0 的历史内核映像与内核地址关联。用户态帧保留原始地址；缺少进程生命周期见证时，不用复用的 PID 猜测历史用户模块。导入启用 StackCaching 的 ETL 时，尚未支持的压缩 StackKey 保留为缺栈状态。

| 列 | 含义 |
| --- | --- |
| 观察到的分配 | 文件中成功解码并保留的分配次数及字节数 |
| 配对释放 | 按地址、会话和池类型匹配到同一观察分配实例的释放 |
| 未观察到释放 | 到文件末尾仍有配对资格、没有对应释放的分配 |
| 不确定 | 地址复用、事件缺口或取消等导致无法确定结果的分配 |

普通池和不同会话池分别配对。重复分配同一地址不会生成虚构的释放；没有前置分配的释放单列为未配对事件。已经报告的覆盖缺口不会因后续成功事件消失。如果 ETL 报告丢事件却没有缺口位置，整段回放不确认生命周期配对，分配量归入不确定。

“未观察到释放”是查找问题的入口，需要结合可重复的业务操作和调用栈判断。采集前已经存在的分配、循环缓冲覆盖掉的事件和未支持的载荷无法补造。文件读取成功和丢事件计数为零也不证明完整的系统分配历史。Pool 分析与 PFN 分类账独立，不从 PFN 未归因量中扣除这些统计。

## 文件、符号和资源边界

- 使用只读离线 ETL 回放和原始 QPC 时钟；关联 StackWalk 的载荷时间戳及线程，冲突的关联保留为未知。
- 当前支持系统 PoolTrace v2 的普通及会话分配/释放事件，验证位宽、字段和长度，未知版本或截断事件显示解码缺口。
- 回放期间锁定输入文件并复核文件身份。读取有时间、事件、活跃分配、分组、调用栈和映像记录上限，可以取消；超限保留缺口状态。
- 本地符号解析只处理身份匹配的历史映像，使用应用共享的 DbgHelp 锁，不自动下载符号。无法匹配时仍显示原始地址及已知模块偏移。
- 文件导航只接受本地磁盘文件；打开的是当前磁盘文件详情，不将其视为历史采集时仍驻留的 DriverObject。

## 开发检查

从仓库根目录运行：

```powershell
pwsh -NoProfile -File tools/Invoke-PoolAllocationAnalysisTests.ps1
pwsh -NoProfile -File tools/Invoke-PoolAllocationAnalysisUiTests.ps1 -QtRoot <Qt MinGW SDK>
```

第一项严格编译分配账本和实际事件解码器，使用构造的事件验证会话隔离、地址复用、缺口、截断、时间顺序和容量边界；端到端检查只启用自有 UUID 的 `PRIVATE_IN_PROC` 提供者，将模拟事件写入临时 ETL 并通过实际 `OpenTrace`/`ProcessTrace` 回放，不录制系统 Pool。会话、提供者和临时文件均由该检查清理。第二项运行真实 Qt 结果页，验证聚合、排序、筛选、后台取消、窗口销毁和布局。正式 MSVC/Qt 主程序构建仍使用 `tools/Invoke-KSwordBuildCheck.ps1`。

事件结构依据本机 Windows 安装的 `MSNT_SystemTrace` MOF 和 TDH 元数据读取，不通过同名私有事件推断。系统 PoolTrace GUID 为 `{0268a8b6-74fd-4302-9dd0-6e8f1795c0cf}`，v2 opcode 32/33 是普通/会话分配，34/35 是普通/会话释放；字段依次为 `Type`、`Tag`、`NumberOfBytes`、`Entry` 和可选 `SessionId`。本机布局匹配不代表所有 Windows 版本都支持该版本。

参考：[Microsoft ETW 事件消费](https://learn.microsoft.com/en-us/windows/win32/etw/consuming-events)、[TDH 事件信息](https://learn.microsoft.com/en-us/windows/win32/api/tdh/nf-tdh-tdhgeteventinformation)、[StackWalk_Event](https://learn.microsoft.com/en-us/windows/win32/etw/stackwalk-event)。
