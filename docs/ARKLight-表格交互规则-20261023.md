# 表格交互与布局改进规则（KswordARKLight）

范围：仅交互与布局（滚动位置、选中保持、列宽、排序指示、双击语义、键盘导航、详情面板比例）。
约束：纯 Win32 + Common Controls；只允许「改常量 / 加 WM_NOTIFY 分支 / 调已有 API」；不重写控件、不引入数据绑定框架。

## 1. 现状问题（现象 → 证据）

**P1 排序后选中按「行号」而非「数据身份」保持 —— 已核实，三套语义并存。**
Windows 页排序只有工具栏 combo（堆叠/进程顺序），切换即触发 `RefreshWindows()` **整表重新枚举重建**，`selectedStableKey` 从未采集：`Features/Window/WindowView.cpp:1229-1242`（`UpdateSortModeFromCombo`→`RefreshWindows`）、`:1081-1092`（`PopulateList` 无 key 采集）、`:1149-1163`。Kernel 页**能**按身份保持（`result->inverse` 反查）：`Features/Kernel/KernelPage.cpp:6470-6499`。模块页**能**按 `stableKey` 保持：`Features/ProcessDetail/ProcessDetailPage.Module.cpp:370-396`(`RestoreListPosition`)、`:794`、`:817-829`。→ 用户无法建立稳定预期。补充：Windows 行**已有** `stableKey`（`:833` `display.stableKey = HwndToText(row.hwnd)`），只是未接线。

**P2 筛选后滚动位置归零 / 顶行漂移 —— 已核实。**
Windows 页筛选后**不恢复选中也不恢复顶行**：`Features/Window/WindowView.cpp:1060-1076`（回调只有 `setVisibleIndexes`+改状态文字）。Registry 页**能**恢复：`Features/Registry/RegistryView.cpp:637-645`(`StableKeyFromListItem`)、`:647-688`(`ApplyValueFilter` 回填 selected/top key)。NetTools 页**能**恢复（`:199-239`），但**手动输入筛选词时传空 key** → 选中与顶行被丢弃：`Features/NetTools/NetToolsConnectionView.cpp:715-717`、`:704`。
根因在共享类 `Ui/VirtualListView.cpp:186-196`：`topIndex` 是**旧可见空间的行号**，筛选/排序后可见空间已重排，该行号指向另一条数据 → 顶行语义漂移；且 `LVSICF_NOSCROLL` 让控件自身不滚动，与 `EnsureVisible(topIndex)` 两股力量互斥。

**P3 刷新时全量重建导致闪烁与选中丢失 —— 已核实。**
`Ui/VirtualListView.cpp:39-47`(`setRows`/`setSharedRows` 每次 `resetVisibleIndexes()`，可见集整体重置 0..N-1)、`:65-71`、`:186-196`(`SetItemCountEx`+`::InvalidateRect` 全表重绘)。→ 未筛选页面一次普通刷新会**闪一次「全量未筛选」**，随后异步筛选再恢复。
重绘锁缺失：`Features/Window/WindowView.cpp:1090`、`Features/Registry/RegistryView.cpp:743`、`Features/NetTools/NetToolsConnectionView.cpp:301` 三处 `setRows/setSharedRows` **无** `ScopedListViewRedrawLock`；对比 `Features/Kernel/KernelPage.cpp:6487`、`Features/File/FileView.cpp:482`、`Features/AuditCommon/AuditTable.cpp:140` 都有。
选中丢失：Windows 页刷新后 `LVN_ITEMCHANGED` 里 `ShowDetail(state, SelectedModelIndex(state))` 用新快照 `itemData`（`Features/Window/WindowView.cpp:1847-1857`）→ **详情面板与列表高亮行错位**。

**P4 列宽全部固定、无实测；resize 时无人生成剩余宽度。**
`Ui/ListViewUtil.h:16` `width = 120` 只是默认值，各页均写死：`Features/Window/WindowView.cpp:871-875`(190/120/300/190/220)、`Features/Registry/RegistryView.cpp:305-312`(220/120/420/260)、`Features/NetTools/NetToolsConnectionView.cpp:636-645`(70/190/80/190/80/110/70/170)。全项目 **0 处**使用 `LVSCW_AUTOSIZE`/`LVSCW_CONTENT`（仅 `Ui/ListViewUtil.cpp:93-94` 注释提及），**0 处**内容实测 API（`GetTextExtentPoint32` 零引用）。列宽只在创建时 `addColumns` 设一次 → 变宽右侧留白、变窄出横向滚动条；全项目 `HDN_` 仅 `Features/ProcessDetail/ProcessDetailPage.Module.cpp:179` 一处 `Header_SetItem`。唯一动态宽度是「显示/隐藏列」用固定像素：`Features/File/FileView.cpp:378-386`。
**刷新会抹掉用户拖拽的列宽**：`Features/Window/WindowView.cpp:1085-1089` 每次 `PopulateList` 都调 `ConfigureWindowColumns`/`ConfigureAuditColumns` → `SetColumn`（`:351-357` 同时写 `LVCF_TEXT|LVCF_WIDTH`）。

**P5 详情面板固定像素，非比例；无可拖动边界。**
`Features/NetTools/NetToolsConnectionView.cpp:58` `kDetailHeight = 168` 固定，`:598-605` 按 `height - kStatusHeight - kDetailHeight` 反推；`Features/Window/WindowView.cpp:54` `kDetailHeight = 210`，`:1661` `height > 480 ? kDetailHeight : height/3` → 仅低于 480px 才退化，是**阈值切换而非比例**。详情面板内部列宽也固定：`Features/NetTools/NetToolsConnectionView.cpp:654-655`(160/700)、`Features/Window/WindowView.cpp:1751-1752`(170/720)。
`Ui/SplitterUtil.h` 已存在（`CalculateSplitterRects`/`HitTestSplitter`/`ClampSplitterPosition`）但**全项目零调用**；真正拖动实现在 Kernel 页手写：`Features/Kernel/KernelPage.cpp:1681-1723`(5 个消息分支)、`:3143-3174`(布局)、`:11910-11930`(`MoveVerticalSplitterFromMouse`)。

**P6 排序指示：仅 1 处有；多级排序：0 处支持。**
指示器只有模块页有：`Features/ProcessDetail/ProcessDetailPage.Module.cpp:166-181`(`UpdateSortIndicator`，用 `HDF_SORTUP/HDF_SORTDOWN`)。Kernel 页列点击排序**无任何指示**：`Features/Kernel/KernelPage.cpp:2483-2487`(`LVN_COLUMNCLICK`→`SortResultRowsByColumn`)。Windows/Registry/NetTools **完全无列点击排序**，Windows 仅工具栏 combo（`Features/Window/WindowView.cpp:1729-1731`），点表头无反应、无「当前排序列」提示。
多级排序全项目 0 处，所有实现都是「单列 + bool 升降序」（`Features/ProcessDetail/ProcessDetailPage.h:496-497`、`Features/Kernel/KernelPage.cpp:6423-6428`）。触发方式还不一致：模块页用**表头子类**+`WM_LBUTTONUP`+`HDM_HITTEST`（`Features/ProcessDetail/ProcessDetailPage.Module.cpp:842-863`，会吞掉表头自身排序箭头行为），Kernel 页用父窗口 `LVN_COLUMNCLICK`。

**P7 键盘：方向键可用，Enter/双击打开详情大面积缺失。**
方向键/PageUp/Home/End 由 ListView 原生支持（**无需改动**）。**Enter 打开详情不可用**：全项目 `VK_RETURN` 仅出现在 `App/MainWindow.cpp:356,364,390`、`Features/Kernel/KernelPage.cpp:1595`、`Ui/TextFindSupport.cpp:579,592`，均为输入框回车；Windows/Registry/NetTools 页 `WM_KEYDOWN` 命中数 **0**。
**双击语义不一致**：Registry 页 `NM_DBLCLK` → 进入子键（`Features/Registry/RegistryView.cpp:1408-1414`）；Windows 与 NetTools 页**均无** `NM_DBLCLK`/`LVN_ITEMACTIVATE`（NetTools 只有 `LVN_ITEMCHANGED`，`:763`）→ 双击**无反应**。且 Registry 该分支因 `PopulateList` 只放 Value 行（`:727-731` 过滤掉 SubKey），`:1410` 的 SubKey 判断**永不命中，是死代码**。

## 2. 规则清单

**A1 统一以 `stableKey` 为身份锚点，禁止用行号跨数据集保持。** 现状：P1 三套语义并存。改法：`Ui/VirtualListView.h` 新增两个只读查询（纯新增，不改既有签名）—— `std::wstring stableKeyAtVisibleIndex(int) const`（实现放 `Ui/VirtualListView.cpp`，复用 `rowAtVisibleIndex()` `:178-184` 取 `rows_[sourceIndex].stableKey`）、`int visibleIndexOfStableKey(const std::wstring&) const`（线性扫 `visibleIndexes_`，未命中返回 -1）。**触及共享类：是**。

**A2 `VirtualListView::updateItemCount()` 改为「先记 key、后按 key 复位」。** 现状：`Ui/VirtualListView.cpp:186-196` 用旧行号复位。改法：①入口先 `topKey = stableKeyAtVisibleIndex(ListView_GetTopIndex(hwnd_))`；②`ListView_SetItemCountEx` 之后若 `topKey` 非空 → `restored = visibleIndexOfStableKey(topKey)`，`restored >= 0` 则 `ListView_EnsureVisible(hwnd_, restored, FALSE)`；③保留 `LVSICF_NOSCROLL`，语义全交第②步。**触及共享类：是**（改动限于 `Ui/VirtualListView.cpp` 一个函数体）。

**A3 Windows 页补「采集 + 回填」连线。** 现状：`Features/Window/WindowView.cpp:1081-1092`、`:1149-1163`。改法：①`PopulateList` 开头采集 `selectedKey = stableKeyAtVisibleIndex(ListView_GetNextItem(state->windowList,-1,LVNI_SELECTED))`、`topKey = stableKeyAtVisibleIndex(ListView_GetTopIndex(state->windowList))`，存入 `WindowViewState`（结构体在 `Features/Window/WindowView.cpp:246` 附近）；②随 `RequestWindowFilter` 下发；③筛选/排序完成回调（`:1060-1076`）中 `setVisibleIndexes` 之后按 key 回填选中（先 `ListView_SetItemState(list,-1,0,LVIS_SELECTED|LVIS_FOCUSED)` 再置目标行），并调 `ShowDetail(state, SelectedModelIndex(state))`。**改 1 文件**（依赖 A1）。

**A4 Registry/NetTools 已按 key 恢复，NetTools 手动筛选路径需补 key。** 现状：`Features/NetTools/NetToolsConnectionView.cpp:715-717`、`:704` 传 `{}, {}`。改法：改用已有 `StableKeyFromListItem`（`:147-155`）采集 selected/top 后传入。**改 1 文件**，Registry 无需改。

**A5 刷新批量重建统一加重绘锁。** 现状：`Features/Window/WindowView.cpp:1090`、`Features/Registry/RegistryView.cpp:743`、`Features/NetTools/NetToolsConnectionView.cpp:301` 无锁。改法：调用点外层加 `Ksword::Ui::ScopedListViewRedrawLock lock(listHwnd);`（已存在 `Ui/ListViewUtil.h:42-53`，用法参考 `Features/File/FileView.cpp:482`），锁范围覆盖 `setRows/setSharedRows` + `setVisibleIndexes`。**改 3 文件，不触及共享类**。

**B1 初始列宽按「表头实测 + 内容抽测」计算。** 现状：P4 全固定。改法：页内匿名 namespace 加静态函数（放在 `Features/Window/WindowView.cpp:351` `SetColumn` 旁）：用 `::GetDC`/`::GetTextExtentPoint32W` + `Ksword::Ui::SystemUIFont()`（`Ui/Controls.h:17`）测量；列宽 = `max(表头宽+24, 内容抽测宽+12)`；内容**只扫前 50 行**（虚拟列表不可全扫，否则上万行卡 UI 线程）；结果经已有 `Ksword::Ui::SetListViewColumnWidth`（`Ui/ListViewUtil.h:73`）写入。建议先在 NetTools 落地验证再推广。**改 1 文件，不触及共享类**。

**B2 resize 时由最后一列吸收剩余宽度；宽度不足时不动。** 现状：P4 无人吸收。改法：在各页 `LayoutView`（`Features/NetTools/NetToolsConnectionView.cpp:569-610`、`Features/Window/WindowView.cpp:1635-1669`）中 `MoveWindow` 列表之后：①`ListView_GetHeader`+`Header_GetItemCount` 取列数；②逐列 `ListView_GetColumnWidth` 求和得 `used`；③`remaining = listClientWidth - used`；④`remaining > 0` → `SetListViewColumnWidth(list, last, currentLast + remaining)`；`remaining < 0` → 不动，交给横向滚动条。**每页 1 文件，不触及共享类**。

**B3 刷新不得覆盖用户已调整的列宽。** 现状：`Features/Window/WindowView.cpp:1085-1089`→`:867-876`→`:351-357` 每次刷新重写标题+宽度。改法：把 `ConfigureWindowColumns`/`ConfigureAuditColumns` 拆为「仅设标题」「仅设宽度」；标题切换时（`UpdateViewModeFromCombo` `:1174-1224`）整体重设，纯刷新路径（`:1149-1163`）**只更新标题不动宽度**；或给 `SetColumn` 增 `bool updateWidth`（默认 true）。**改 1 文件，不触及共享类**。

**C1 详情面板高度改比例（默认 1/3），去掉固定 px 阈值分支。** 现状：`Features/Window/WindowView.cpp:1661`、`Features/NetTools/NetToolsConnectionView.cpp:58`+`:598`。改法：前者 → `const int detailHeight = (std::max)(80, height / 3);`；后者 `:58` 改比例常量、`:598` → `detailTop = (std::max)(listTop, height - kStatusHeight - (std::max)(80, height / 3));`。**改 2 文件，不触及共享类**。

**C2 可拖动边界：照抄 Kernel 页内联模式，不引入 SplitterUtil（说明理由）。** 现状：P5，Kernel 页已手写一套可用的。**为什么不用 SplitterUtil**：它只提供**纯几何**函数（`CalculateSplitterRects`/`HitTestSplitter`/`ClampSplitterPosition`），不含消息循环与状态；而拖动必需的「捕获鼠标 / 光标形态 / 偏移量持久化」仍要自己写，引入反多一层间接。改法（以 NetTools 为例，`Features/NetTools/NetToolsConnectionView.cpp`）：①`ConnectionViewState`（`:84-100`）加 `int detailHeightPx = 0;`（0 表示用默认比例）；②`LayoutView`（`:569-610`）算出 `detailTop` 后若 `detailHeightPx > 0` 则覆盖比例值；③在 `ConnectionViewProc`（`:669`）增 `WM_SETCURSOR`/`WM_LBUTTONDOWN`/`WM_MOUSEMOVE`/`WM_LBUTTONUP`/`WM_CAPTURECHANGED` 五分支，逻辑对齐 `Features/Kernel/KernelPage.cpp:1681-1723`；④夹取：详情最小 80px、列表最小 120px。**改 1 文件，不触及共享类**。可选第二阶段把此逻辑上提到 `Ui/SplitterUtil.h` 扩展为带状态控制器 —— **属共享类改动，需单独立项**，本轮不做。

**D1 为 Kernel 页补排序指示器。** 现状：P6 无指示。改法：把 `Features/ProcessDetail/ProcessDetailPage.Module.cpp:166-181` 的 `UpdateSortIndicator` 逻辑（`Header_GetItem` 读 `HDI_FORMAT` → 清 `HDF_SORTUP|HDF_SORTDOWN` → 对当前列置位）**照搬**到 `Features/Kernel/KernelPage.cpp` 的 `SortResultRowsByColumn`（`:6409-6430`）之后调用；并在 `sortColumn_ = -1` 的三处重置点（`:5395`、`:5486`、`:5876`）清一次指示。也可提到 `Ui/ListViewUtil.h` 新增 `UpdateListViewSortIndicator(HWND,int,bool)` 供多页复用 —— **属共享类新增 API**，本轮按照搬落地。**改 1 文件，不触及共享类**。

**D2 Windows/Registry/NetTools 三页加列点击排序。** 现状：P6 只有 combo 或全无。改法：统一走父窗口 `LVN_COLUMNCLICK`（与 Kernel 页一致，**不用表头子类**）：①在各页 `WM_NOTIFY` 加 `LVN_COLUMNCLICK` 分支（Windows 页 `Features/Window/WindowView.cpp:1839-1865` 已有 WM_NOTIFY 块，直接加 `if`）；②点击列 → 翻转/设置 `sortColumn`+`sortDescending` → 重排**已保留的行快照**（不重新枚举）；③重排在数据层做（Worker 或本地 `std::stable_sort`），参照 `Features/ProcessDetail/ProcessDetailPage.Module.cpp:319-359`，比较器已有现成实现 `Ksword::Ui::CompareCellsNumericAware`（`Ui/NumericSortKey.h:41`）。**改 3 文件，不触及共享类**。风险：Windows 页若**继续复用** `RefreshWindows()`（`:1241`）会整表重枚举、代价高且丢选中 → 必须改为「只重排 `state->filterRows` 的顺序」；与 A3 同属一条改造线。

**D3 多级排序：先加「次级排序键」单级扩展，暂不做 Shift+点击多列。** 现状：P6 全项目 0 处。改法：排序状态由「`int sortColumn`+`bool descending`」扩为「`primaryColumn`+`primaryDescending`+`secondaryColumn`(-1 无)」；主键不等才比次键；次键 tie-break 仍用 `CompareCellsNumericAware`（`Ui/NumericSortKey.h:41`）。落点：`Features/ProcessDetail/ProcessDetailPage.h:496-497`、`Features/Kernel/KernelPage.cpp:6423-6428`。**改 2 文件，不触及共享类**。**可发现性配套**：表头无法表达两列排序，故用**状态栏文本**表达 —— `Features/Window/WindowView.cpp:1896` 的 `state->statusText` 已有绘制路径，如 `L"Windows: 按 Title 升序（次级：PID 降序）"`。**本轮不做 Shift+点击累加**，多级可发现性成本主要在提示。

**E1 统一双击语义为「打开详情」，各页补 `NM_DBLCLK`/`LVN_ITEMACTIVATE`。** 现状：P7 Registry=进子键、Windows/NetTools=无反应。改法：Windows 页加 `NM_DBLCLK` → 打开该窗口的进程详情（复用已有 `OpenSelectedWindowProcess` `Features/Window/WindowView.cpp:1417-1436`，不新写业务逻辑）；NetTools 页加 `NM_DBLCLK` → 打开该连接的进程详情（复用页内 `RequestEntityNavigation` 路径 `:552-559`）；Registry 保留「进子键」但因 `PopulateList` 只放 Value 行（`:727-731`）该分支**永不命中**，建议改为「双击=把值写入编辑器并聚焦」或删除 —— **需确认**产品预期。**改 2–3 文件，不触及共享类**。

**E2 列表获焦时 Enter 等同双击（打开详情）。** 现状：P7 列表场景 0 处处理。改法：在 Windows 页 `WM_KEYDOWN` 判 `wParam == VK_RETURN` 且 `GetFocus() == state->windowList` → 复用 E1 同一入口（避免两套逻辑）。注意页内 `FocusFilterBar(state->filterBar)`（`Features/Window/WindowView.cpp:1835`）会把焦点抢到筛选框，Enter 语义天然分给筛选框，列表聚焦时才生效，语义不冲突。**Win32 中 ListView 默认不把 `WM_KEYDOWN` 转发给父窗口**，故若走父窗口分支不可靠，需 `SetWindowSubclass` 挂到列表 HWND。**推荐改用 `LVN_ITEMACTIVATE`**（列表内置，Enter 与双击都触发）覆盖键盘路径，`NM_DBLCLK` 只留鼠标路径 —— **需确认** `LVS_OWNERDATA` 下 `LVN_ITEMACTIVATE` 是否照常发送。**改 2 文件，不触及共享类**。

**E3 方向键/PageUp/Home/End 保持现状，不做改动。** 现状：ListView 原生支持（P7）。**不要**在这些键上插自定义处理，否则破坏原生滚动。唯一需确认：所有列表均经 `CreateReportListView` 创建，已带 `WS_TABSTOP`（`Ui/ListViewUtil.cpp:39`），Tab 可达。

## 3. 最小实现顺序（按风险从低到高）

| 5 | A5 刷新加重绘锁 | 3 | 否 | 低 | `ScopedListViewRedrawLock` 已存在，直接套用 |
