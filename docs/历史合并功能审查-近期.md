## 此前确认缺失、本轮已恢复：Tab 循环中的 CMD 节点

`5bf035cf` 增加标题栏输入框的四节点循环：全局、当前页面、当前表格、CMD；`Tab` / `Shift+Tab` 可连续切换。`45799b38` 撤回该改动，后续 `52c84fb5` 没有恢复；父分支 `7f6ae8f9` 虽移除错误的额外 connect，却仍保留有效的 `requestCommandInputActivation` → `activateCommandInput` 接线。`a7018d28` 的 merge-base 是已含四节点的 `15be030c`，父一则继承 `45799b38` 的删除结果；它延续父一回退，未从父二恢复，不能算第二次独立单侧吞改。恢复前只循环三个搜索范围，不能从当前表格按 Tab 切到 CMD，也不能从 CMD 按反向快捷键回到搜索范围。

优先级 P2。恢复前的证据为 `Ksword5.1/Ksword5.1/UI/GlobalUiSearch.cpp:996`：键盘循环只在 `m_searchModeActive` 时处理；旧 `:1818` 的 `kScopeCount = 3` 将循环限定为三个搜索范围。CMD 菜单仍在 `Framework/CustomTitleBar.cpp:642`、`:753`，因此影响边界是键盘模式切换入口，不是 CMD 执行能力整体消失。

菜单双模式搜索/CMD，以及 popup 内的三个搜索范围当时仍存在；它们不能补偿上述快捷键入口。`5c934552` 将范围控件移到 popup 前，其父提交已经没有 CMD 循环，因此不能将此缺失归为该后续 UI 重构主动删除。

本轮恢复已与现有 popup 设计整合：`GlobalUiSearchController::cycleSearchScope` 在三个搜索范围边界发出 `requestCommandInputActivation`，CMD 中的 Tab/Shift+Tab 返回首尾搜索范围，并由主窗口接到标题栏激活槽；没有整段复制含错误 connect 的旧父提交。菜单、搜索范围和 CMD 提交入口继续保留，模式切换不提交命令，异步搜索结果在切离搜索时取消或失效。真实 Qt 三组件离屏测试最终 128 项断言、0 失败、退出码 0，包含 results-only 结果和首批异步 chunk 仍排队时取消的严格用例。标准语言审计 27485 个源文本引用、退出码 0；主程序 Release/x64 构建 `BUILD_RESULT=SUCCESS`、`EXIT_CODE=0`、`I18N_AUDIT_PASSED=True`。日志与产物摘要见总报告。这不能替代生产 GUI 或实际命令执行验收。
