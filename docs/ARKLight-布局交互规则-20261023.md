# KswordARKLight 布局与交互改进规则清单

> 范围：仅布局/间距/密度/对齐/断点/滚动责任/控件尺寸/交互。不含配色、圆角、动画。
> 最大动作：新增无状态自由函数 + 改现有常量 + 改 MoveWindow/创建参数。

---

## 1. 现状结构

主窗口实际是**两层半**，不是三层：

| 层 | 归属 | 尺寸来源 | 问题 |
|---|---|---|---|
| 菜单行 | `HMENU` 非客户区 | 系统 | 命令输入框是 `WS_POPUP` 悬浮其上（`App\MainWindow.cpp:632`），不占布局 |
| 工作区 | `DockManager` 子窗口 | `layout()` 把整个客户区减去页脚（`App\MainWindow.cpp:1488-1494`） | 无左导航栏；导航靠 `Ctrl+K` 弹出 LISTBOX（`App\MainWindow.cpp:697`），无固定导航层 |
| 页脚 | `statusText_` STATIC | `kStatusHeight = 18`（`App\MainWindow.cpp:55`），关闭态变 40/66（`:1477`） | 18px 低于中文 12px 行的舒适下限；绘制分隔线在 `rc.bottom - kStatusHeight`（`:1844`），与 STATIC 实际占位不重合 |

**常量现状（真实值）**

- 主窗口：`kCommandEditWidth=320`、`kCommandEditHeight=22`、`kCommandEditMenuGap=8`、`kStatusHeight=18`、导航面板 `560x440`（`App\MainWindow.cpp:50-55`）
- Dock：`kTabHeight=22`、`kTabMinWidth=52`、`kTabMaxWidth=140`、`kSplitterSize=4`、`kFloatingWidth=540`、`kFloatingHeight=380`（`Docking\DockManager.cpp:16-22`）
- 页面（**每个文件各自复制一份，无共享头**）：`kGap=6`、`kRowHeight=24`、`kHeaderHeight=kGap*3+kRowHeight*2=66`、`kStatusHeight=22`，见 `Features\NetTools\NetToolsConnectionView.cpp:55-59`、`Features\HardwareStats\BusDeviceView.cpp:45-49`、`Features\WindowTools\WindowToolsClipboardView.cpp:50-54` 等 12+ 处
- **不一致**：`kHeaderHeight` 三种值并存 —— `66`（NetTools 系计算值）、`64`（`Features\Hardware\HardwareView.cpp:33`）、`68`（`Features\Misc\MiscFeature.cpp:58`）
- **不一致**：间距节奏是 **6px**，不是 4/8/16。全项目无 4/8/16 栅格

**结构性缺陷**

1. `MainWindow::layout()`（`:1466`）只调 `dockManager_->layout()`，而 `DockManager::layout`（`:409`）只做一次 `MoveWindow` + `layoutChildren()`。**状态栏宽度变化时不通知 DockManager**，`dockBounds.bottom` 变了但页内 WM_SIZE 不重发（实际上 MoveWindow 会发，OK），但页脚高度只在 `closing` 时才非 18 —— 状态栏本身不参与任何断点。
2. 主窗口**没有 `WM_GETMINMAXINFO`**（全项目仅 `Ui\EvidenceSessionView.cpp:370`、`Features\Process\ProcessView.cpp:229`、`Features\ProcessDetail\ProcessDetailPage.Module.cpp:492` 有）。窗口可缩到任意小，所有页面 `std::max(0, ...)` 静默塌陷为 0 高度，无下限保护。
3. 页签溢出**静默丢弃**：`DockManager::paintLeaf`（`:653-679`）和 `hitTestTab`（`:968-1002`）都在 `x >= tabs.right` 时 `break`，无「还有 N 个」指示，无滚动，无溢出菜单。
4. DockManager **无任何 `WM_KEYDOWN` 处理**（grep 确认），页签只能用鼠标切换。
5. `positionCommandInput()` 被调用 8 次（`:471/476/486/536/646/763/803/1066/1518/1526`），是独立于 `layout()` 的第二条定位路径 —— 两条路径职责重叠。

## 2. 布局规则

### 2.1 间距节奏

**L1｜统一到 4/8/16 栅格，废弃 6px。**
- 现状：`kGap=6` 遍布 12+ 文件（`NetToolsConnectionView.cpp:55`、`BusDeviceView.cpp:45`、`MiscFeature.cpp:59`、`HardwareView.cpp:34`…）；`Docking\DockManager.cpp:19` 另有 `kSplitterSize=4`（不同语义却同值）。
- 改法：新增 `Ui\Controls.h` 内三个 `constexpr int kSpaceXs=4/kSpaceSm=8/kSpaceLg=16`；把各页面 `kGap` 定义改为 `constexpr int kGap = kSpaceSm;`（一行替换，语义即对齐）。`kSplitterSize` 保持 4 但注释区分语义。

**L2｜垂直节奏：一个页面里出现的所有 y 坐标必须是 `y0 + n*8`。**
- 现状：`NetToolsConnectionView.cpp:576` `firstRowY=kGap(6)`、`:592` `secondRowY=6+24+6=36`，而 `kHeaderHeight=66`，`36+24+6=66` 恰好闭合 —— 这是巧合，`StartupView.cpp:702-707` 用 `kGap, 35, kGap` 硬写 35（`HardwareView.cpp:713` 同样写 35），35 不是任何栅格值。
- 改法：把 `StartupView.cpp:702-707` 与 `HardwareView.cpp:712-713` 的 `35` 改为 `kGap * 2 + kRowHeight`（=36）。共 2 文件 4 处。

**L3｜`kHeaderHeight` 只有一个定义。**
- 现状：`66`（计算式，NetTools 系 6 文件）、`64`（`HardwareView.cpp:33`）、`68`（`MiscFeature.cpp:58`）、`66`（字面量，`StartupView.cpp:52`）。
- 改法：`HardwareView.cpp:33` 改 `constexpr int kHeaderHeight = kGap * 3 + kRowHeight * 2;`；`MiscFeature.cpp:58` 同改。差异消失，页面顶部工具条基线统一。

### 2.2 参数区与结果区的高度分配

**L4｜详情区用「自然高度 + 上限」，不用无脑固定 px。**
- 现状：`kDetailHeight` 全部硬编码且互不相同 —— `168`（`NetToolsConnectionView.cpp:58`）、`180`（`BusDeviceView.cpp:48`、`UsbTopologyView.cpp:47`）、`200`（`NetToolsFirewallView.cpp:54`）、`220`（`StartupView.cpp:54`）、`120`（`ContextMenuView.cpp:57`）。
- 改法：新增 `Ui\Controls.h` 自由函数 `int DetailPaneHeight(int contentHeight, int naturalRows)`，实现 `clamp(naturalRows*kRowHeight + kSpaceSm, contentHeight/3, contentHeight/2)`；各 `LayoutView` 把 `height - kStatusHeight - kDetailHeight` 换成 `DetailPaneHeight(height, 6)`。改动面大但每处 1 行，**建议放到最后做**。

**L5｜`StartupView.cpp:709` 的 500px 断点是唯一正确的模式，应作为全局范式。**
- 现状：`const int detailHeight = height > 500 ? kDetailHeight : std::max(80, height / 3);` —— 矮窗口降级为 1/3。
- 改法：把该表达式提取为 `Ui\Controls.h` 的 `ResponsivePaneHeight(int height, int natural, int minRows)`，先在 `StartupView.cpp` 保持行为不变地抽出，再逐页替换。

**L6｜`listHeight` 的 `max(0, ...)` 会产生 0 高度列表，必须夹到最小可见高度。**
- 现状：`NetToolsConnectionView.cpp:599`、`BusDeviceView.cpp:480`、`UsbTopologyView.cpp:484`、`ServiceView.cpp:940`、`ContextMenuView.cpp:586` 全是 `(std::max)(0, detailTop - listTop - kGap)` —— 窗口够矮时列表高度变 0，用户看不到任何行，也没有任何提示。
- 改法：改为 `max(kRowHeight * 2, ...)`，并让详情区在 `listTop + kRowHeight*2 + kGap` 之前就让位（把 `detailTop` 的 `max(listTop, ...)` 换成 `max(listTop + kRowHeight*2, ...)`）。**但更优做法是先做 R7**（主窗口最小宽度约束），从根上避免触发。

### 2.3 窄窗口断点

**R7｜主窗口加 `WM_GETMINMAXINFO`，`ptMinTrackSize = 1024 x 640`。**
- 现状：`App\MainWindow.cpp:322-589` 的 `WndProc` 无此消息，窗口可缩到 0。初始尺寸 `CenterWindowRect(1240, 780)`（`:278`）也说明 1024 是设计下限附近。
- 改法：在 `handleMessage` 的 `switch`（`:426`）最前面加
  ```cpp
  case WM_GETMINMAXINFO: {
      auto* info = reinterpret_cast<MINMAXINFO*>(lParam);
      info->ptMinTrackSize.x = 1024; info->ptMinTrackSize.y = 640; return 0; }
  ```
  1 文件 6 行，零风险。**这一条挡掉下面 80% 的塌陷问题。**

**R8｜工具条按钮行在 `width < 640` 时折行到第二行，`kHeaderHeight` 随之从 66 变 96。**
- 现状：`NetToolsConnectionView.cpp:577-585` 的 `place()` lambda 只加 `cursorX`，从不检查是否超出 `width`；5 个控件在窄窗口会直接跑出客户区被裁掉。`StartupView.cpp:702-706` 5 个按钮硬写 `x += 84` 同样问题。`CallbackMonitorView.cpp:611` 更糟：`8 + index*80` 完全无视窗口宽度。
- 改法：`place()` 内加 `if (cursorX + controlWidth + kGap > width) { cursorX = kGap; rowY += kRowHeight + kGap; }`；`kHeaderHeight` 改为 `constexpr int kHeaderHeightBase` + 运行时 `headerHeight = (wrapped ? kHeaderHeightBase + kRowHeight + kGap : kHeaderHeightBase)`，`listTop` 用后者。涉及 `NetToolsConnectionView.cpp`、`BusDeviceView.cpp`、`NetToolsFirewallView.cpp`、`StartupView.cpp`、`HardwareView.cpp`、`CallbackMonitorView.cpp` 共 6 文件。**优先级低于 R7。**

**R9｜详情面板在 `width < 720` 时收起（不占布局），而非压成 120px 细条。**
- 现状：`WindowToolsHierarchyView.cpp:535` `listWidth = max(160, (width - kGap*3) * 45 / 100)`，宽度 400 时 `listWidth=160`、右栏 224 —— 两栏都进入不可用状态。`WindowToolsClipboardView.cpp:596` `detailWidth = max(120, (width-kGap*3)/2)` 同样。
- 改法：`width < 720` 时 `ShowWindow(detail/report/preview, SW_HIDE)` 并把列表拉满宽；`width >= 720` 恢复。断点值写成一个 `constexpr int kTwoPaneMinWidth = 720` 放 `Ui\Controls.h`。

**R10｜`HardwareView` 的树/详情分栏已有断点，保留但对齐命名。**
- 现状：`HardwareView.cpp:715` `const int treeWidth = width > kTreeWidth + 260 ? kTreeWidth : width / 2;` —— 这是全项目唯一的分栏断点，写法可读但阈值 260 是魔数。
- 改法：把 `260` 提为文件内 `constexpr int kTreeCollapseSlack = 260;` 并加注释「详情最小可用宽」。行为不变，纯可读性。1 行。

### 2.4 表格列宽与详情面板宽度

**C11｜列宽总和超过可用宽时，最后一个弹性列承担压缩。**
- 现状：`NetToolsConnectionView.cpp:636-645` 列宽 `70+190+80+190+80+110+70+170 = 960px` 硬编码；`StartupView.cpp:735-738` `230+130+120+90+360+360 = 1290px`。两者在 1024 窗口下都产生横向滚动条。
- 改法：`ListViewUtil.cpp` 已有 `SetListViewColumnWidth`（`:92`）。新增自由函数 `void FitLastFlexibleColumn(HWND list, int lastIndex, int targetTotal)`：在 `LayoutView` 末尾（`NetToolsConnectionView.cpp:609` 之后）调用，把最后一列设为 `max(80, visibleWidth - sum(前 n-1 列))`，从而消除横向滚动。用户手工拖过的列宽会被覆盖 —— **需确认是否接受**，若不接受则改为「仅当总宽 > 可见宽时生效」。

**C12｜详情双列表（属性/值）用比例而非固定 160/700。**
- 现状：`NetToolsConnectionView.cpp:654-655` `AddColumn(detail,0,L"属性",160)` / `(1,L"值",700)`；`HardwareView.cpp:740-741` `180/560`；`StartupView.cpp:739-740` `170/760`。三套值，同一视觉角色。
- 改法：新增 `void SizeDetailColumns(HWND list, int totalWidth)`，属性列 `totalWidth/5`、值列 `totalWidth - 属性列 - kSpaceSm`；三处各替换为一次调用。与 C11 同一时机调用，共用一次宽度计算。3 文件。

**C13｜`kFloatingWidth/Height` 固定 540x380，窄于工作区时反而更小。**
- 现状：`DockManager.cpp:21-22` 固定值，`WM_CREATE`（`:600-605`）直接用它。
- 改法：`WM_CREATE` 里改为 `min(kFloatingWidth, ownerWidth * 2/3)` / `min(kFloatingHeight, ownerHeight * 2/3)`。1 文件 2 行。

### 2.5 滚动责任

**S14｜滚动责任：只有结果列表滚；工具条/筛选条/状态条固定。当前已正确，需固化为规则。**
- 依据：`NetToolsConnectionView.cpp:788-792` 状态条在 `WM_PAINT` 里手绘（不占布局、不滚），`filterBar` 在 `listTop` 之上固定（`:594`），只有 `connectionList`/`detailList` 是真实 WS_VSCROLL 控件。
- 改法：不改代码。在 `Ui\Controls.h` 顶部注释写死这条约定，供后续页面遵守。

**S15｜`CallbackMonitorView.cpp:604-623` 的魔数布局必须清理，它是滚动责任的反例。**
- 现状：`8 + index*80`、`:616` filter 在 y=72、`:619` list 在 y=106、`:622` status 在 `height-26` 且**高 20 会与 list 底部重叠**（list 底 = `106 + max(80, height-110-116-32)` = `height-152`，不重叠，但 `height < 258` 时 list 高度被 `max(80,...)` 撑到 80，底 = 186 > `height-26`，**重叠**）。另 `:617` `detailHeight=116` 是局部常量，`:618` 的 `110`/`32` 无注释。
- 改法：整体重写为 `kGap/kRowHeight/kHeaderHeight/kStatusHeight` 四常量 + `listTop = kHeaderHeight`，与其它 11 个页面对齐。1 文件 ~20 行，**收益高（消除重叠 bug）**。

**S16｜`LoadingOverlay` 只覆盖列表区，不覆盖详情区 —— 保持。**
- 依据：`NetToolsConnectionView.cpp:608`、`BusDeviceView.cpp:489` 均只 `MoveWindow(overlay, kGap, listTop, ..., listHeight)`。这让详情区在加载期间仍可读，是有意设计，不要改成全屏遮罩。

## 3. 交互规则

### 3.1 页签

**I17｜页签溢出必须有可见指示（最高优先交互缺陷）。**
- 现状：`DockManager.cpp:676-678` 绘制时 `if (x >= tabs.right) break;`，超出的页签**完全不画**；`hitTestTab`（`:995`）同样 `break`，点不到。用户会以为页签不存在。
- 改法（不改框架，只加绘制）：`paintLeaf`（`:644`）在循环 `break` 之后，若 `ordinal + 1 < leaf->docks.size()` 且还有可见 dock，在 `tabs.right - 24` 处绘制 `L"…"` 或 `"+N"`（N = 剩余可见 dock 数），并作为可点击区域：`hitTestTab` 在 `:995` 的 break 前先判断 `left >= leaf->tabRect.right - 24` 则返回 `ordinal = 首个溢出项`。约 20 行，1 文件。
- 备选（更省）：把 `kTabMaxWidth`（`:18`）从 140 降到 100，配合 `kTabMinWidth=52` 可多容纳 2-3 个页签。**1 行**，建议与上一条一起做。

**I18｜页签键盘导航：DockManager 增加 `WM_KEYDOWN` 处理 `Ctrl+Tab/Ctrl+Shift+Tab/Ctrl+PageUp/Down`。**
- 现状：DockManager 完全不处理键盘（grep 无 `WM_KEYDOWN`）。
- 改法：`Docking\DockManager.cpp` 的 `handleMessage` switch（`:462`）加
  ```cpp
  case WM_KEYDOWN:
      if ((GetKeyState(VK_CONTROL) & 0x8000) && (wParam == VK_TAB || wParam == VK_PAGEUP || wParam == VK_PAGEDOWN)) {
          StepActiveDock(wParam == VK_PAGEUP || (wParam == VK_TAB && (GetKeyState(VK_SHIFT)&0x8000)), hwnd);
          return 0; }
      break;
  ```
  `StepActiveDock` 是新增无状态自由函数，在当前 leaf 的 `docks` 里前后移动 `activeDock` 并调 `activateDock()`（`:353`）。约 25 行，1 文件。

**I19｜页签拖拽后焦点必须回到活动页内容。**
- 现状：`activateDock`（`:353`）与 `WM_LBUTTONUP`（`:518`）后无 `SetFocus`。用键盘 Tab 时焦点可能仍在 DockManager 宿主上。
- 改法：`activateDock` 末尾加 `if (HWND c = docks_[index]->content()) ::SetFocus(c);`。1 行。

**I20｜焦点顺序：状态栏 STATIC 不应可获焦。**
- 现状：`Controls.cpp:51` `CreateText` 用 `WS_CHILD | WS_VISIBLE | SS_LEFTNOWORDWRAP`，**无 `WS_TABSTOP`**，已正确。`CreateButton`（`:60`）有 `WS_TABSTOP`，正确。**无需改动**，记录为规则。

### 3.2 表格排序/筛选后的状态保持

**I21｜`VirtualListView::updateItemCount` 的 topIndex 保持有一处真实缺陷。**
- 现状：`Ui\VirtualListView.cpp:190-194`
  ```cpp
  const int topIndex = ListView_GetTopIndex(hwnd_);
  ListView_SetItemCountEx(..., LVSICF_NOINVALIDATEALL | LVSICF_NOSCROLL);
  if (topIndex >= 0 && topIndex < visibleIndexes_.size()) ListView_EnsureVisible(hwnd_, topIndex, FALSE);
  ```
  用的是**可见索引位置**，不是 stableKey。筛选后 `topIndex` 这个位置对应的行已完全改变 → 视口跳到无关行。
- 改法：`NetToolsConnectionView.cpp` 已经在做正确的事（`:215-231` 按 `selectedStableKey` / `topStableKey` 还原，`:231` `ListView_EnsureVisible(list, topItem, FALSE)`）。把这段逻辑下沉：在 `VirtualListView.h` 加 `void setRowsKeepingViewport(std::vector<VirtualListRow> rows, std::wstring topKey)`（先取当前 top 行的 `stableKey` → `setRows` → 找到新 index → `EnsureVisible`）。然后 `NetToolsConnectionView.cpp:231` 可简化为调用它。2 文件。**其它 11 个 VirtualListView 使用方（Process/Handle/File/Service/Monitor…）同病，需确认是否统一替换。**

**I22｜排序后选中项保持：`NetToolsConnectionView.cpp:729-735` 已做，但只对协议筛选生效。**
- 现状：`:730` 先取 `StableKeyFromListItem(当前选中)`，`:732` `BuildRows` 重建，`:734` 再把它传给 filter。其它页面（`ServiceView.cpp:900`、`StartupView.cpp:696`）无此处理。
- 改法：把「取 stableKey → 重建 → 传回」三步固化为 `VirtualListView` 的成员函数 `rebuildKeepingSelection(fn)`，逐页替换。**改动面大，放最后。**

### 3.3 双击 / 右键语义

**I23｜右键菜单统一入口，但双击目前无统一语义 —— 建议双击 = 打开详情。**
- 现状：`NetToolsConnectionView.cpp:770-775` 处理 `NM_RCLICK` → `ShowConnectionContextMenu`；`MiscFeature.cpp:63-64` 用 `kMenuCopyCell` 区分单击单元格。**全项目无一处处理 `NM_DBLCLK`**（grep 确认）。列表双击当前等价于两次单击 → 触发两次 `LVN_ITEMCHANGED` → 两次 `RefreshSelectionDependentUi`，无害但无意义。
- 改法：在 `NetToolsConnectionView.cpp:775` 后加
  ```cpp
  if (header->code == NM_DBLCLK) { RefreshSelectionDependentUi(*state); return 0; }
  ```
  统一「双击=刷新详情/打开详情」。后续页面按此语义对齐。1 文件 3 行。

**I24｜右键菜单弹出前必须确保右键所在行被选中。**
- 现状：`NetToolsConnectionView.cpp:770-773` 直接用光标位置弹菜单；若点在未选中行上，`ShowConnectionContextMenu` 内的 `entry` 取的是旧选中项 → 菜单「复制选中行」复制的是上一行。
- 改法：`NM_RCLICK` 分支内先 `hitTest = ListView_HitTest(list, &pt)`（client 坐标，`ScreenToClient`），若命中有效项且非当前选中则 `ListView_SetItemState` 选中它，再弹菜单。约 8 行，1 文件。**这是真实功能 bug，优先级高于 I23。**

**I25｜列表应加 `NM_RCLICK` 的默认返回 0，避免父窗口收到 WM_CONTEXTMENU 弹系统菜单。**
- 现状：`NetToolsConnectionView.cpp:775` 已 `return 0`，正确。记录为规则，其它页面（`MiscFeature.cpp`、`StartupView.cpp`）需核对。
