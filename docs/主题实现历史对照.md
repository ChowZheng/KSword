# 主题实现历史对照

核对日期：2026-10-04。历史基线是本地 Git 对象；“本次”指当前未提交工作区的主题修复，基于 `a4747f619299f201ff30fa88d9c0e0d51786f719`。本报告只核对主题相关源码与合并历史，不新增构建或运行验证。

## 核对结论

`efffa24e85c7e784b7ab6f924dc6f178da4f7a34` 没有删除主题 RGB 偏移体系，也没有把已经完整实现的“所有强调角色随用户主题色变化”退回固定配色。该完整能力在可见历史里没有实现过：主题角色引入时就有独立固定 RGB 种子，后来新增自定义主题色时明确只替换蓝色种子。

本次工作包含两类：补齐既有主题能力的遗漏路径，以及按用户要求扩展颜色派生范围。两者都改善了实际主题跟随，但不能全部称为原样恢复。

本轮后续截图反馈又明确了顶部ADS导航的颜色要求：导航新增独立三态，全部以主体色派生；普通业务QTabBar和中性背景继续保留各自角色。该补充及全项目13组待修配色问题见`docs/全项目配色审计.md`，下表中既有通用角色的默认视觉边界不能用于推断新的ADS导航像素。

合并确实引入了新的利用率浮窗及其独立 palette、缩放样式快照。旧主题切换流程只更新在场控件，没有迁移浮窗保存的旧 palette/QSS；退出浮窗会把旧值写回。这属于新增功能的主题传播缺口，本次已接通刷新和返还链路。

## 不能混淆的默认视觉边界

默认角色种子精确保留，不等于所有原页面每个像素都不变。八处原固定磁盘/网络曲线改为统一性能角色时，默认值如下：

| 路径/角色 | 合并前固定 RGB | 本次默认深色 | 本次默认浅色 |
| --- | --- | --- | --- |
| 磁盘 Read（旧聚合与设备页） | `(80,170,255)` | `(97,190,255)` | `(71,164,255)` |
| 磁盘 Write（旧聚合与设备页） | `(255,190,105)` | `(255,159,46)` | `(231,133,20)` |
| 网络 Rx（旧聚合与设备页） | `(92,190,255)` | `(97,190,255)` | `(71,164,255)` |
| 网络 Tx（旧聚合页） | `(153,129,255)` | `(255,159,46)` | `(231,133,20)` |
| 网络 Tx（设备页） | `(255,190,105)` | `(255,159,46)` | `(231,133,20)` |

以上数值由原固定 QColor 与当前 `PerformanceColor(Read/Write)` 默认分支计算得到，未施加自定义种子的 3:1 校准。箭头、勾号和 ADS 图标也有从黑白/平台色改为主题色的视觉变化。

## 角色种子方案的真实来源

`2e5a947f` 首次集中定义：Blue `(67,160,255)`，Purple `(184,99,255)`，Green `(47,125,50)`，Orange `(217,119,6)` 等，共 13 个固定种子。

`1a0e395b` 将原“统一深浅亮度偏移 + 单个角色偏移”改为每个角色显式深浅总偏移；`93891e0b` 继续调整配色对比。它们都没有将多个种子归并为一个主种子。

`09bd94d1` 新增自定义色后，只有 Blue 变为 `PrimaryAccentColor()`。搜索可见历史的 `AccentSeed`/`PrimaryBlueColor` 变更，没有发现随后曾统一全部种子、又被 merge 退回独立固定种子的实现。

本次 `AccentSeedOffset` 的数值来自旧角色种子减默认 Blue 种子。例如 Purple 是 `(184,99,255)-(67,160,255)=(117,-61,0)`，Green 是 `(-20,-35,-205)`，Orange 是 `(150,-41,-249)`。这是本次采用的兼容方案：默认值完全还原旧表，用户换主色时全部强调角色一起移动，再做既有深浅偏移和必要对比校准。
