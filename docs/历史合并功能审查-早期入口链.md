## 抽取方法与计数口径

可复现脚本是 [audit_early_merge_entry_chains.py](../tools/audit_early_merge_entry_chains.py)，结果位于现有 `.codex-build-logs/early-merge-entry-chains.json`。

```powershell
py -3.13 tools/audit_early_merge_entry_chains.py --output .codex-build-logs/early-merge-entry-chains.json
```

脚本只读 Git 与工作区文本，不 checkout、不构建、不执行程序。每个合并取两父和 merge-base，筛选 `MainWindow.cpp/.h`、`PluginHost.cpp/.h` 及 `ProcessDock/`、`FileDock/`、`NetworkDock/`、`KernelDock/`、`MonitorDock/` 内的 C++ 源码。对相对 base 任一父改变的选定路径读取 base、两父和合并结果，再抽取 `connect`、`addTab`、Dock 创建、菜单安装 helper、相关窗口实例化和自定义菜单策略。

- **494 是“合并 × 选定路径”观察记录数**，不是 494 项功能，也不是唯一文件数。同一路径在多个合并中计多次；每条读取四个 revision 的内容并复用 blob 缓存。
- 14 条观察记录为两父相对 base 都改变且两父 blob 真正不同的路径；其中只有 `ca74c7ef` 的 FileDock.cpp 与 KernelDock.cpp 整文件采用第一父。相同 blob 在两分支出现不算“选一父”。
- **22 是 `(merge, path, parent_index)` 候选组**，共包含 45 个父侧存在、合并文本中不再完全相同的规范化入口标记。一个组可含多条信号连接；同一迁移可在后继合并重复出现，故不是 22 项功能损失。
- 所有 22 组的 `missing_added` 均为空：选定标记中，没有发现“父相对 base 独有新增、却未进入合并”的入口标记。仍逐条审查既有标记移除，因为父提交主动替换菜单也可能遗漏旧动作。
- 另读回每组的两父和结果 blob：22 组的整个合并文件都等于已经改写入口的另一父（13 组等于第二父、9 组等于第一父）。这些入口移除先发生在父分支，未由合并冲突新造出来。保留这个来源分类，同时继续核实其改写是否真的保住旧能力。
- `absent_head` / `absent_workspace` 是全选定范围内同形标记集合比较，用于定位迁移，不能单独证明可调用。报告的保留判断还检查了当前控件注册、信号/菜单分支和下游实现。

这是 Qt/C++ 文本候选工具，不是 C++ AST 或功能证明器。lambda 调用集合变化、变量重命名、`qOverload` 模板逗号、带连接类型的五参数 connect 都可能产生同形标记差异；字符串内容、条件含义、QAction 的 `exec` 分支和跨文件路由通过下面的人工审查确认。未变动的外部模块不因此得到全量运行验收。
