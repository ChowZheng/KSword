## 当前恢复实现

输入框中普通 Tab 按 Global → CurrentPage → CurrentTable → CMD → Global 循环，Shift+Tab 反向循环；同时兼容 `Key_Backtab` 和带 Shift 的 `Key_Tab`。Ctrl/Alt/Meta+Tab 继续透传，搜索及 CMD 弹层内部字段的 Tab 保持原焦点顺序。切换不执行命令，也不改输入文本。

| --- | --- |
| 搜索进入 CMD | `GlobalUiSearch.cpp:1848::cycleSearchScope` 在 CurrentTable 正向或 Global 反向边界先 `dismissPopup` 取消在途扫描，再发 `requestCommandInputActivation(true)`；`MainWindow.cpp:6679` 连接 `CustomTitleBar::activateCommandInput`（`:934`）。 |
| CMD 返回搜索 | `GlobalUiSearch.cpp:996` 的 KeyPress 分支在 CMD 中识别 Tab/Shift+Tab，分别选 Global/CurrentTable 并发 `requestSearchInputActivation(true)`；反向选择表格前清旧显式目标，让最近交互上下文生效。 |
| 两个弹层状态 | 复用 `CustomTitleBar.cpp:964` 的 `inputModeChanged`：MainWindow 原接线关闭/展开 CMD 配置弹层，控制器 `setSearchInputActive` 同步搜索扫描和弹层。保留菜单双模式与 popup 三个范围标签，不回退布局。 |

## MainWindow 九条独有行的解释

历史库存中九条去重独有行混合了三种内容：

1. `requestCommandInputActivation -> activateCommandInput`、`searchScopeSelectionRequested -> selectSearchScope`：前者四模式切换本轮恢复；后者旧标题栏范围入口由现有 popup 三范围标签承担，不复制旧菜单接线。
2. 两参数 `searchScopeDisplayTextChanged` 回调与 `setSearchScopeSelection`：用于旧标题栏范围菜单回显；当前弹层 QTabBar 与单参数范围提示承担回显，不能仅凭原行消失认定范围完全失效。
3. `CustomTitleBar::setSearchScopeDisplayText -> GlobalUiSearchController::setSearchScopeDisplayText`：15be 误加而没有控制器对应方法，7f6 明确删除以修复构建；这部分不应恢复。

本轮恢复以 `5bf035cf` 的交互算法、或 `7f6ae8f9` 的修复后接线为依据，兼容当前 popup 范围控件与 `CommandExecutionPopup`，没有整文件回退或照搬库存中的九行。
