# 历史合并功能审查：旧引用与多共同祖先

日期：2026-10-04。固定 Git 基线为 `a4747f619299f201ff30fa88d9c0e0d51786f719`。全引用库存共 119 个合并，其中 81 个是此 HEAD 的祖先，本报告覆盖其余 38 个。这里只读审查历史对象与当前调用链，没有修改生产源码、构建、运行 CLI、加载驱动或操作生产 GUI。本轮写入仅为审查脚本、JSON 证据和本文；主程序恢复及其验证记录见总报告和近期报告。

本范围未确认新增的、需要恢复到当前生产代码的功能损失。这个结论限定于下述候选和调用链：它不代表 38 个旧分支的所有运行行为均与当前 Qt 主线相同，更不代表全部 UI、R0 或设备操作已验收。旧分支确实有历史行为缩减，但必须区分合并选取、父提交主动清理、占位按钮和不曾进入当前主线的新能力。

## 方法与计数边界

`tools/audit_old_merge_refs.py` 重新运行每个合并的 `git merge-base --all`，核对库存的完整共同祖先集合，并对每一个基准分别读取 base / 双父 / merge 的递归 tree/blob。38 个合并均有两个父提交；其中 32 个有一个共同祖先、5 个有两个共同祖先、1 个无共同祖先。多基准时没有任意挑一个 base 作结论，也没有把不存在的共同祖先替换成空树。

“单侧变化”指仅一父相对指定 base 改变的路径；“差异”指合并 blob 不等于变化侧 blob，包含有意修改和保留被另一侧删除的文件。计数是路径数，不是功能数。只有对所有共同祖先均成立的单侧差异才列为一致候选；双侧胜出及自定义结果仍另作人工检查。完整证据见 `.codex-build-logs/old-merge-base-audit.json`，安全语义复核见 `.codex-build-logs/old-reference-semantic-check.json`。

库存源代码候选还按当前定义、调用者、菜单/信号入口核对；仅当前 blob 不等于旧父 blob，不能说明仍有损失。历史 AI/API 文件只在内存比较去掉全部字面量和注释后的结构，不保存配置值；报告和 JSON 不包含密钥、请求地址或授权头。

### WMI / ETW：历史变化和当前策略分开

`8658c055` 的 `EventMonitor::initializeETW` 调用 `generateUniqueSessionName()`；`d1385ee5` 和 `44efab1e` 的自定义监控结果删除这条调用，后续五组重复合并沿用此结果。这确实是旧分支的会话命名行为缩减，不应写成“所有父侧行为无损”。旧 `Win32_ProcessStartTrace` 查询也从专用 `SELECT * FROM Win32_ProcessStartTrace` 改为与 StopTrace 一起拼 `WITHIN 1`；UI 事件选择、`startMonitoring(selectedTypes)` 和进程事件接收分支没有删除。旧未知接口的 QueryInterface 日志被改写，不能从删除一条诊断文字推出整个监控入口消失。

当前使用新的 `MonitorDock`：WMI 页的开始订阅入口创建 `SELECT * FROM <class>` 并调用 `ExecNotificationQuery`（`MonitorDock.cpp:9832` 附近、`:9995`、`:10002`）；进程创建/退出事件仍经现行事件类选择订阅。ETW 采用显式 `KswordEtw` 会话重用，启动前清理已有同前缀会话，并在 `ERROR_ALREADY_EXISTS` 后重建（`:12632`、`:12633`、`:12759`、`:12760`）。它与旧时间后缀策略不同，不能假称时间后缀已恢复；当前监控 UI 和独立会话生命周期没有因这些非主线祖先的旧合并失去调用链。未实测 WMI/ETW 或多用户会话。
