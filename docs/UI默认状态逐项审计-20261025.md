## 已完成的消息框自然首帧复现与修复

- 原实现用 `git show 1849efb3:Ksword5.1/Ksword5.1/UI/ThemedMessageBox.cpp` 读取并原样编译主题/事件过滤器，平台图标、WindowChrome 与翻译为明确薄适配。自然 `QMessageBox::information` 的首个真实 Paint 后下一轮窗口尺寸变化：短正文 `122×110 → 360×110`，200字符长正文 `122×110 → 653×110`，均已使用最终主题但尺寸不稳定。并非只把 show() 返回或强制 render 当作实际首帧。
- 修复：Show 同步下发默认样式/按钮/宽度约束；由于 QMessageBox 自身 showEvent 会重算 wrap/fixed size，在首个窗口 UpdateRequest、backing-store Paint 之前完成所属布局 activate，并将单个 LayoutRequest 交还 QMessageBox 自身计算最终尺寸。此后旧 timer 受 revision/weak-lifetime 门禁取消；实际换肤/字体变化仍合并。没有全应用 processEvents，没有在 Paint 改布局，没有计时猜稳定。
- 修复后自然首 Paint 与后续同一窗口尺寸：短正文 `360×110 → 360×110`，长正文 `653×110 → 653×110`。
- 正式回归：`python tools/test_message_box_first_frame.py --qt-root "$KSWORD_QT_DIR"`，33项检查、8次首次 Paint，通过。覆盖浅/深、短/长静态 information/warning、modeless首显/重显、完整共享样式/按钮度量、旧请求不重复改变样式/几何、显式刷新及同步销毁。
- 临时自然负控驱动 对同一自然首帧夹具的独立旧版负控 对旧实现退出1，`ready=1 stable=0`；默认工作树修复后退出0，`ready=1 stable=1`。
- 以上为 Linux 真 QtWidgets offscreen；不代替主程序 HostX64/MSVC、Windows原生标题栏/图标以及完整产品GUI验收。
